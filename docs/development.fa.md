# توسعهٔ API

[English](development.md) · [فارسی](development.fa.md)

از نسخهٔ Node در `.nvmrc` و فرمان `npm ci` برای نصب وابستگی‌ها استفاده کنید.
API پروژه‌ای مستقل است؛ کد اجرایی آن را به checkout دیگری پیوند ندهید. پیش از
تغییر راه‌اندازی یا ترکیب لایه‌ها، [README](../README.fa.md) و
[معماری](architecture.fa.md) را بخوانید. فایل‌های محیط خصوصی و دادهٔ محلی
موجود را حفظ کنید؛ آزمون‌ها دادهٔ مصنوعی خود را دارند.

برای یافتن لایه‌ها از [مسیر‌یابی](source-navigation.fa.md)، برای تغییر رفتار از
[توسعهٔ قابلیت](feature-development.fa.md) و پیش از انتشار از
[اعتبارسنجی](validation.fa.md) استفاده کنید. تغییر قرارداد HTTP ممکن است به
هماهنگی انتشار با مصرف‌کنندگان مستقل نیاز داشته باشد.

اجرای محلی و قالب‌های استقرار اثبات آمادگی تولید نیستند؛ ارسال OTP در تولید
هنوز پیاده‌سازی نشده است. [استقرار](deployment.fa.md) پیش‌نیازهای اپراتور و
محدودیت بررسی‌ها را توضیح می‌دهد.

## ابزار مهاجرت پایگاه داده

`npm run server:generate` بدون نیاز به `DATABASE_URL` از schema مهاجرت تولید
می‌کند. `npm run server:migrate` مهاجرت را اجرا می‌کند و به `DATABASE_URL`
صریح نیاز دارد؛ فقط پایگاه داده‌ای را انتخاب کنید که مجاز به تغییر آن هستید.
اعتبارنامهٔ واقعی و فایل‌های محیط خصوصی را بیرون Git نگه دارید.

## سازگاری وابستگی‌ها

هنگام تغییر زنجیرهٔ ابزار یا وابستگی‌های آن، Drizzle Kit و override محدود
esbuild را بازبینی و اعتبارسنجی کنید. Knip فایل `drizzle.config.ts` و schema را
نقطهٔ ورود ایستا می‌داند؛ plugin مربوط به Drizzle غیرفعال است و موفقیت Knip
کشف وابستگی‌ها توسط آن plugin را تأیید نمی‌کند.

نسخهٔ اصلی Node.js 24 و `@types/node` باید یکسان باشد. تا زمانی که نسخهٔ نصب‌شدهٔ
`typescript-eslint` فقط بازهٔ `>=4.8.4 <6.1.0` را پشتیبانی می‌کند، TypeScript روی
یک نسخهٔ سازگار 6.0 می‌ماند؛ محدودیت سازگاری را برای نصب TypeScript 7 نادیده نگیرید.
پیش از تغییر این محدودیت، [بازهٔ پشتیبانی رسمی](https://typescript-eslint.io/users/dependency-versions/)
را بررسی کنید.

`better-auth`، `@better-auth/drizzle-adapter` و override مربوط به `@better-auth/core`
را با هم به‌روز کنید. override محدود esbuild برای بارگذار قدیمی Drizzle Kit باید
حفظ شود و سازگاری و امنیت زنجیرهٔ ابزار بررسی شود؛ نسخهٔ همهٔ مصرف‌کنندگان
esbuild را به‌اجبار یکسان نکنید. از نسخه‌های
پایدار استفاده کنید، lockfile را تازه کنید و پس از به‌روزرسانی وابستگی‌ها، پروفایل
کامل اعتبارسنجی را اجرا کنید. ناسازگاری درخت وابستگی را با `--force` یا
`--legacy-peer-deps` پنهان نکنید.
