# توسعهٔ API

[English](development.md) · [فارسی](development.fa.md)

از نسخهٔ Node در `.nvmrc` و فرمان `npm ci` برای نصب وابستگی‌ها استفاده کنید.
API پروژه‌ای مستقل است؛ کد اجرایی آن را به checkout دیگری پیوند ندهید. پیش از
تغییر راه‌اندازی یا ترکیب لایه‌ها، [README](../README.fa.md) و
[معماری](architecture.fa.md) را بخوانید. فایل‌های محیط خصوصی و دادهٔ محلی
موجود را حفظ کنید؛ آزمون‌ها دادهٔ مصنوعی خود را دارند.

برای یافتن لایه‌ها از [مسیر‌یابی](source-navigation.fa.md)، برای تغییر رفتار از
[توسعهٔ قابلیت](feature-development.fa.md) و پیش از انتشار از
[اعتبارسنجی](validation.fa.md) استفاده کنید. تغییر قرارداد HTTP ممکن است به
هماهنگی انتشار با مصرف‌کنندگان مستقل نیاز داشته باشد.

اجرای محلی و قالب‌های استقرار اثبات آمادگی تولید نیستند؛ ارسال OTP در تولید
هنوز پیاده‌سازی نشده است. [استقرار](deployment.fa.md) پیش‌نیازهای اپراتور و
محدودیت بررسی‌ها را توضیح می‌دهد.

## سازگاری وابستگی‌ها

نسخهٔ اصلی Node.js و `@types/node` را یکسان نگه دارید. بازهٔ فعلی peer برای
`typescript-eslint` از TypeScript `>=4.8.4 <6.1.0` پشتیبانی می‌کند؛ هنگام
به‌روزرسانی [بازهٔ بالادستی](https://typescript-eslint.io/users/dependency-versions/)
را بررسی کنید. `better-auth`، `@better-auth/drizzle-adapter` و override مربوط
به `@better-auth/core` را با هم به‌روز، lockfile را تازه و پروفایل کامل را اجرا
کنید. ناسازگاری درخت وابستگی را با `--force` یا `--legacy-peer-deps` پنهان نکنید.
