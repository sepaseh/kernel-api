# آزمون‌های API

[English](testing.md) · [فارسی](testing.fa.md)

مجموعهٔ منتشرشده سرویس‌ها، رفتار HTTP، احراز هویت، تراکنش‌های پایگاه داده،
گزارش‌گیری، ترجمه و ذخیره‌سازی را با داده‌های مصنوعی و ایزوله بررسی می‌کند.
فرمان‌های دقیق در [فهرست اعتبارسنجی](../.agents/validation.json) و `package.json`
نگهداری می‌شوند؛ فهرست نام فایل‌ها به‌تنهایی اثبات پوشش نیست.

`npm run test:recovery` سه تمرین ایزولهٔ بازیابی و رخداد را اجرا می‌کند. آن‌ها
در `test:coverage` نیز اجرا می‌شوند. دامنهٔ آن‌ها در [تمرین‌های بازیابی](recovery-drills.fa.md)
آمده است. آزمون امضای ذخیره‌سازی فقط از loopback استفاده می‌کند و MinIO مستقر
نیست. آزمون HTTP محلی نیز اثبات عملکرد کلاینت مستقر یا ارائه‌دهندهٔ پیامک نیست.

آزمون اختیاری Docker پروژه، builder، image و دادهٔ موقت خود را دارد؛
[استقرار Docker](../deploy/docker/README.fa.md) را ببینید. آزمون بومی بستهٔ Node
را در سیستم میزبان بررسی می‌کند و لزوماً systemd یا Nginx را اجرا نمی‌کند.
هنگام پاک‌سازی هرگز منابع پروژهٔ دیگری را حذف نکنید.

اگر توقف سرور آزمون بومی ظرف ۱۰ ثانیه تأیید نشود، بسته و دادهٔ موقت حفظ می‌شوند و خطا گزارش می‌شود. پس از توقف تأییدشده، حذف هر دو منبع مستقل امتحان می‌شود.

آزمون‌های مجموعه، هشت پاسخ محدودیت درخواست احراز هویت را با ساعت کنترل‌شده با نمونه‌های ذخیره‌شده مقایسه می‌کنند. این آزمون‌ها `Retry-After` محدودکنندهٔ درون‌فرایندی را بررسی می‌کنند؛ محدودکنندهٔ توزیع‌شده یا آمادگی تولید را اثبات نمی‌کنند.

آزمون اختیاری استقرار بومی، وابستگی‌های اجرایی را در بستهٔ متعلق به آزمون نصب
می‌کند، پایگاه دادهٔ موقت را مقداردهی و سلامت و ورود سرور بسته‌بندی‌شده را
بررسی می‌کند. این آزمون پلتفرم میزبان فعلی را می‌سنجد و اجرای مدیر سرویس لینوکس
در ویندوز را اثبات نمی‌کند. smoke داکر برای هر اجرا builder مستقل دارد و تصاویر،
cache و داده‌های متعلق به آزمون را پس از موفقیت، شکست یا لغو قابل‌رسیدگی پاک
می‌کند؛ خطای پاک‌سازی باعث شکست فرمان می‌شود. [سیاست پاک‌سازی داکر](../deploy/docker/README.fa.md)
و [رکوردهای QA](qa/README.fa.md) را برای نتیجه و محدودیت بررسی ببینید.
