# Manual release metadata

[English](releasing.md) · [فارسی](releasing.fa.md)

از تغییر بازبینی‌شده، بررسی‌های تأییدشده و PR یا ادغام با مجوز صریح استفاده
کنید. [راهنمای عملیات انتشار](release-operations.fa.md) نگهداری بسته، سازگاری
و بازگشت را توضیح می‌دهد؛ [حفاظت شاخه](branch-protection.fa.md) بررسی‌های
راه دوری را شرح می‌دهد که باید واقعاً بررسی شوند، نه از فایل محلی نتیجه گرفته شوند.

[تاریخچهٔ تغییرات](../CHANGELOG.fa.md) یادداشت نسخه‌های منتشرشده را ثبت می‌کند؛
تنظیم نسخه به‌تنهایی اثبات انتشار نیست.

هدف گردش‌کار release-please و تنظیمات آن آماده‌کردن metadata و PR انتشار با
درخواست دستی است؛ وجود آن اثبات تنظیم یا اجرا نیست. قرار نیست image
عملیاتی منتشر، سرویس فعال یا DB تغییر داده شود. برای commit درخواست‌شده Conventional Commits
به‌کار ببرید؛ تکمیل کپی به‌تنهایی مجوز commit/push نیست.
[عملیات انتشار](release-operations.fa.md) مالک تأیید artifact، سازگاری، checksum،
فعال‌سازی و rollback و [حفاظت branch](branch-protection.fa.md) توضیح‌دهندهٔ سیاست
remote است که هنوز تنظیم و تأیید صریح لازم دارد.

گردش‌کار ابتدا secret مخزن به نام `RELEASE_PLEASE_TOKEN` را استفاده می‌کند و
در نبود آن به `GITHUB_TOKEN` برمی‌گردد. وقتی سیاست مخزن اجازهٔ ساخت PR توسط
GitHub Actions را نمی‌دهد، یک token اختصاصی با دسترسی نوشتن به محتوا و PR همان
مخزن لازم است؛ در آن سیاست، token جایگزین نمی‌تواند PR انتشار بسازد. نگهدارندهٔ
مجاز باید secret و سیاست مخزن را تنظیم و اجرای واقعی workflowها و بررسی‌های
الزامی را تأیید کند. وجود PR به‌تنهایی نشانهٔ اجرا یا موفقیت بررسی‌ها نیست.
مقدار token را افشا نکنید.

Release Please فایل انگلیسی `CHANGELOG.md` را به‌روز می‌کند و فایل فارسی
`CHANGELOG.fa.md` را خودکار تغییر نمی‌دهد. پیش از ادغام PR انتشار، یادداشت
فارسی را مطابق یادداشت انگلیسی تولیدشده آماده و بازبینی کنید و هر دو فایل را
در PR بررسی کنید.

آزمون محلی و قالب‌های موجود اثبات انتشار مستقر یا ارسال OTP در تولید نیستند.
اعتبارنامه، دادهٔ خصوصی یا دادهٔ آزمون را به‌عنوان بستهٔ انتشار ارسال نکنید.
