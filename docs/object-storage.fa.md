# ذخیره‌سازی شیء

[English](object-storage.md) · [فارسی](object-storage.fa.md)

آداپترهای ذخیره‌سازی، رابط کاربردی `ObjectStorage` را با فایل محلی و MinIO
سازگار با S3 پیاده می‌کند. فایل `storage/create.ts` آداپتر را از روی
`ServerConfig.storageDriver` انتخاب و درایور ناشناخته را صریحاً رد می‌کند.
ساخت آداپتر، API را راه‌اندازی و `ensureReady` را فراخوانی نمی‌کند. نقطهٔ اتصال
آیندهٔ برنامه باید پیش از پذیرش بارگذاری، آماده‌سازی را با `await` کامل کند.
[معماری](architecture.fa.md) و [بررسی کامل مرحله](bootstrap.fa.md) را ببینید.

## فایل محلی

فایل `storage/local.ts` در دو محل عمومی و خصوصی زیر پوشهٔ تنظیم‌شده می‌نویسد.
ایجاد انحصاری است؛ کلید تکراری نمی‌تواند شیء موجود را بازنویسی کند. خطای نوشتن
یا بستن، باعث تلاش برای حذف فقط فایل تازهٔ همان فراخوانی می‌شود و خطای اصلی حفظ
می‌شود. شکست پاک‌سازی ممکن است بایت ناقص را برای رسیدگی مسئول نگهداری باقی
بگذارد. خواندن و حذف فایل مفقود با خطا روبه‌رو می‌شوند.

این پوشه باید در اختیار فرایند API باشد. محصور بودن متنی مسیر، جلوی ساخت
symlink توسط کاربر دارای دسترسی سیستم‌عامل را نمی‌گیرد. نشانی عمومی به مسیر
محتوای آیندهٔ API اشاره می‌کند؛ پوشه را منتشر نمی‌کند و وجود مسیر یا مجوز آن
را ثابت نمی‌کند.

## MinIO با S3 SDK

فایل `storage/minio.ts` از `@aws-sdk/client-s3` در زیرساخت استفاده می‌کند.
نام درایور و تنظیمات همان `minio` است؛ SDK رابط کاربرد را تغییر نمی‌دهد و تایپ
اختصاصی AWS وارد آن نمی‌کند. آداپتر اعتبارنامه، endpoint، نشانی‌دهی path-style
و منطقهٔ امضا را صریح تعیین می‌کند. گزینهٔ اختیاری `MINIO_REGION` یا
`ServerConfig.minio.region` به‌طور پیش‌فرض `us-east-1` است؛ برای استقرار با منطقهٔ
دیگر، منطقهٔ واقعی سرور را تنظیم کنید. منطقه برچسب ASCII با طول ۱ تا ۶۳، شامل
حروف، رقم و خط تیرهٔ میانی است و دو سر آن باید حرف یا رقم باشد. بزرگی و کوچکی
حروف حفظ می‌شود؛ نام‌های مستعار FIPS که SDK بازنویسی می‌کند رد می‌شوند. تنظیم
منطقه در محیط یا پروفایل AWS جای این تنظیم صریح را نمی‌گیرد. اعتبارنامه از
پروفایل میزبان یا فرادادهٔ ماشین انتخاب نمی‌شود. تغییر مسیر منطقه یا endpoint
HTTP دنبال نمی‌شود؛ منطقهٔ نادرست یا redirect با خطا متوقف می‌شود و درخواست به
endpoint نامرتبط فرستاده نمی‌شود.

از طریق شیء تنظیمات موجود، میزبان، درگاه معتبر، وضعیت TLS، کلیدهای دسترسی و
محرمانهٔ صریح و غیرخالی، نام پایهٔ bucket و نشانی عمومی را تحویل دهید. اعتبارنامه
را commit نکنید و در نشانی عمومی نگذارید. خارج از `localhost` و نشانی loopback
صریح IPv4 یا IPv6، TLS الزامی است. نام DNS راه‌دور صرفاً با حل شدن به نشانی
محلی، مشمول استثنای loopback نمی‌شود.

آداپتر فقط `<base>-private` و `<base>-public` را در اختیار می‌گیرد. فضای نام و
هویت سرویس اختصاصی با مجوز عملیات لازم bucket، versioning، policy و شیء روی
همین دو bucket به کار ببرید. آماده‌سازی هر دو را بررسی یا ایجاد می‌کند، نبود
versioning را می‌سنجد، policy دستهٔ خصوصی را حذف و مجوز عمومی `s3:GetObject` را
فقط روی دستهٔ عمومی نصب می‌کند. سایر سیاست‌های هویت سرویس، مجوزها و کنترل‌های
بیرونی بر عهدهٔ مسئول نگهداری‌اند. این دسته‌ها را با نویسنده یا policy نامرتبط
مشترک نکنید. آماده‌سازی ممکن است پس از موفقیت چند عملیات قبلی شکست بخورد؛
تراکنش نیست و پس از شکست نباید وضعیت آماده اعلام شود.

عملیات `put` ایجاد شرطی با `If-None-Match: *` دارد. برخورد کلید بدون بازنویسی
بایت قبلی رد می‌شود؛ نویسنده‌های هم‌زمان باید این خطا را مدیریت کنند. عملیات
`get` کل پاسخ SDK را در یک `Uint8Array` نگه می‌دارد و خطای جریان را عبور
می‌دهد؛ رابط جریان برای فایل با اندازهٔ نامحدود نیست. حذف شیء مفقود طبق رفتار
idempotent سرویس S3 موفق است و با خطای فایل مفقود در آداپتر محلی تفاوت دارد.
فایل `storage/operations.ts` می‌تواند بدون جایگزین کردن خطای اصلی، گزارش امن بدهد.

## حذف قطعی و ارجاع عمومی

حذف نرم ممنوع است. در آماده‌سازی و پیش از هر نوشتن یا حذف، وضعیت versioning
باید غایب باشد. حالت فعال، تعلیق و هر وضعیت موجود دیگر رد می‌شود؛ آداپتر
versioning را غیرفعال نمی‌کند و حذف برای ساخت نشانگر versioning نمی‌فرستد.
تنظیمات bucket باید زیر کنترل مدیریتی بمانند: بررسی versioning و سپس حذف در
برابر تغییر هم‌زمان تنظیمات توسط فرد دارای مجوز، اتمیک نیست. این آداپتر تاریخچهٔ
نسخه‌های از قبل موجود را مدیریت نمی‌کند. بررسی ارجاع کاری همچنان متعلق به
قواعد کاربرد و ماندگاری است؛ حذف شیء مجوز حذف رکورد کاری نمی‌دهد.

فقط bucket عمومی متعلق به برنامه می‌تواند نشانی عمومی MinIO داشته باشد.
ارجاع خصوصی نشانی عمومی ندارد. اعتبارسنجی bucket و کلید، دستهٔ بیگانه، بخش
خالی یا نقطه‌ای، بک‌اسلش، نویسهٔ کنترلی و کلید بیش از اندازه را رد می‌کند.
نشانی پایهٔ عمومی خارج از loopback باید HTTPS و بدون اعتبارنامه، query یا
fragment باشد. هر بخش کلید جداگانه percent-encode می‌شود تا معنای کلید دارای
Unicode و نویسهٔ رزروشده حفظ شود. نشانی، ارجاع است و وجود شیء را ثابت نمی‌کند.

## اعتبارسنجی و محدودیت آن

پیش از commit یا تحویل PR مجاز، [بررسی کامل مرجع](../.agents/validation.json)
را روی محتوای دقیق پیشنهادی اجرا کنید. تست فایل‌سیستم از پوشهٔ موقت تازه و
متعلق به خود استفاده و داده‌هایش را پاک می‌کند. تست ذخیره‌سازی از S3 SDK واقعی
با سرور HTTP محلی متعلق به تست، اعتبارنامهٔ مصنوعی و بررسی مستقل امضای درخواست
استفاده می‌کند. فایل پروفایل AWS خالی و جدا، غیرفعال بودن کشف فراداده و محافظ
شبکهٔ خارجی، تست را از اطلاعات خصوصی میزبان مستقل می‌کنند. سرور و منابع متعلق
به تست پس از اجرا جمع می‌شوند.

تست‌ها ایجاد و خطای bucket، policy، رد versioning، ایجاد شرطی و هم‌زمان، بایت
دقیق خالی و باینری و Unicode، خواندن و حذف، اعتبارسنجی نشانی و خطای پاسخ را
می‌سنجند. این شاهد رفتار SDK و پروتکل مقابل سرور مصنوعی است؛ سازگاری با نسخهٔ
مستقر MinIO، اعتبارنامه و TLS عملیاتی، اجرای سیاست بیرونی، مجوز HTTP یا برنامهٔ
قابل اجرا را ثابت نمی‌کند. پیش از true شدن `applicationReady`، اتصال به
سرویس‌های واقعی و دورریختنی و بررسی کامل HTTP، احراز هویت، پایگاه داده و
ذخیره‌سازی همچنان لازم است.
