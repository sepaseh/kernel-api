# اعتبارسنجی API

[English](validation.md) · [فارسی](validation.fa.md)

[فهرست اعتبارسنجی](../.agents/validation.json) مرجع فرمان‌ها و پروفایل‌ها است.
در زمان توسعه کوچک‌ترین بررسی مرتبط را اجرا کنید؛ پیش از هر commit یا push
مجاز، روی نسخهٔ دقیق پیشنهادی `npm run validate -- full` را اجرا کنید. بررسی
شکست‌خورده یا در دسترس‌نبود‌ه موفق محسوب نمی‌شود؛ نتیجه و دامنه‌اش را گزارش
کنید. CI الزامی PR نیز از پروفایل کامل استفاده می‌کند.

فهرست فعال و اجراکنندهٔ اعتبارسنجی مخصوص همین API مستقل هستند. پروفایل
`workspace` در آن‌ها تعریف یا اجرا نمی‌شود؛ پروفایل کامل همچنان پیش از commit و
push مجاز الزامی است.

فقط از دادهٔ مصنوعی و موقت استفاده کنید. [آزمون‌ها](testing.fa.md) شواهد و
محدودیت‌ها را توضیح می‌دهند و [راهنمای Sonar](sonarqube.fa.md) اجرای scanner،
معیار کیفیت و گزارش کامل موارد را تفکیک می‌کند. موفقیت محلی اثبات استقرار،
ارسال OTP در تولید یا بازبینی موفق از راه دور نیست.

آزمون‌های عملی Docker و انتشار بومی اختیاری و نیازمند اجرای صریح هستند؛
پروفایل کامل آن‌ها را اجرا نمی‌کند. [راهنمای استقرار](deployment.fa.md) را
ببینید و سیستم‌عامل و نتیجهٔ واقعی را گزارش کنید.

بررسی snapshot فهرست فایل‌های منتشرشده، از جمله نمونه‌های مجموعه و آزمون‌های fixture را اعتبارسنجی می‌کند. فایل‌های محلی اضافی به‌طور خودکار بخشی از نسخهٔ پیشنهادی نیستند؛ محتوای دقیق موردنظر را اعتبارسنجی کنید و اجرای پوشهٔ کاری را شاهد نسخه‌ای دیگر ندانید.

از fixture ساختگی و موقت استفاده کنید، نه فایل محیط، دادهٔ مالک یا API موجود.
شکست شبکه یا سرویس audit به معنی اعتبارسنجی ناتمام است، نه نتیجهٔ سالم. سیاست
PR و Sonar و workflowهای staging، smoke و DAST محدودهٔ جداگانه دارند. workflowهای
CodeQL و release نیز محدودهٔ خود را دارند. وجود تنظیمات، اجرای remote یا حفاظت
شاخه را ثابت نمی‌کند. manifest، نمای settings، CI، مسیرهای راهنما
و مستندات دو زبانه را هماهنگ نگه دارید.
