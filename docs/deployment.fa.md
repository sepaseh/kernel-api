# Independent API deployment

[English](deployment.md) · [فارسی](deployment.fa.md)

قالب‌های مستقل استقرار برای این دو روش فراهم‌اند:
[Docker/Compose](../deploy/docker/README.fa.md) و
[Linux بومی با systemd/Nginx](../deploy/native/README.fa.md). این قالب‌ها و آزمون‌های
ساختگی آمادگی محیط عملیاتی یا تولید را ثابت نمی‌کنند و ارسال واقعی OTP هنوز
پیاده‌سازی نشده است. فقط همین مخزن ساخته
و اجرا می‌شود. مبدأ عمومی API و مبدأ دقیق پنل و وب‌سایت خارجی را مشخص کنید؛
کد برنامهٔ دیگر یا شبکهٔ Docker مشترک لازم نیست. برای میزبانی هم‌زمان، یک edge
مدیریت‌شده با upstreamهای دارای پورت متفاوت به‌کار ببرید. server blockهای نام‌دار
را در آن ادغام و برای هر آدرس شنود فقط یک جفت block پیش‌فرض رد میزبان نگه دارید؛
بارگیری چند قالب کامل مستقل، `default_server` تکراری ایجاد می‌کند. چند gateway
را به پورت یکسان میزبان متصل نکنید.

API از TypeScript مستقیم Node.js 24 و مهاجرت‌های بررسی‌شدهٔ شروع استفاده می‌کند.
SQLite و فایل عمومی/خصوصی بیرون release تغییرناپذیر پایدار می‌مانند. پیش‌بررسی
عملیاتی اعتبارنامهٔ نمونه، مبدأ عمومی ناامن، مسیر محلی نسبی، مسیر DB و آپلود درون
انتشار تغییرناپذیر (حتی از راه پیوند پوشه)، OTP و seed توسعه و نبود شناسهٔ انتشار
را رد می‌کند. شناسه‌های نمونهٔ انتشار باید با شناسهٔ واقعی و تغییرناپذیر جایگزین شوند.
میزبان HTTP ناشناخته قطع و اتصال TLS با نام ناشناخته رد می‌شود.
entrypoint Docker و ExecStartPre بومی آن را
اجباری می‌کنند. bootstrap عملیاتی جدا و صریح، فقط روی DB خالی، با JSON محافظت‌شده
از STDIN و محیط تعیین‌شده انجام می‌شود.
پیش‌بررسی برای پایگاه داده فقط URL محلی SQLite از نوع `file:` با مسیر مطلق و
پایدار بیرون release و بدون میزبان، query یا fragment را می‌پذیرد. استقرار
libSQL راه‌دور در این بسته اعتبارسنجی نشده است.

`deploy:package` انتشار API انحصاری می‌سازد؛ `deploy:render` فیلدهای عمومی معتبر
را از stdin در قالب ثابت `bootstrap` یا `kernel` جایگزین و با حفظ متغیر Nginx به
stdout می‌نویسد؛ `deploy:check -- api` محیط عملیاتی صریح و
`deploy:health -- api` آمادگی معنایی را بررسی می‌کند. این‌ها env توسعه را نمی‌خوانند
و DNS یا گواهی نمی‌سازند. `test:deploy` فقط fixture محلی ساختگی دارد. اجرای
`test:deploy:docker` به موتور Linux محلی نیاز دارد و TLS و اعتبارنامه و volume
خود را می‌سازد؛ Docker context راه‌دور استفاده نمی‌شود. CI معمول استقرار راه‌دور ندارد.

ارسال واقعی OTP با پیامک/ایمیل هنوز پیاده نشده است. حساب bootstrapشده با رمز
وارد می‌شود؛ ثبت‌نام، بازیابی و تأیید ایمیل عملیاتی به آداپتور ارسال نیاز دارند.
OTP ثابت توسعه در تولید ممنوع است. backup رویهٔ اپراتور است و زمان‌بندی خودکار
ندارد. پیش از ارتقا [بازیابی](backup-restore.fa.md) و
[انتشار و rollback](release-operations.fa.md) را بخوانید.
