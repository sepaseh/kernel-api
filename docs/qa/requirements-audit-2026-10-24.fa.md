# ممیزی نیازمندی‌های API — ۲۴ اکتبر ۲۰۲۶

[English](requirements-audit-2026-10-24.md) · [فارسی](requirements-audit-2026-10-24.fa.md)

این پرونده گزارشی تاریخی دربارهٔ ۲۴ اکتبر ۲۰۲۶ است؛ ادعاهای اجرای آن مستقلاً تأیید نشده‌اند و وضعیت کنونی پروژه را نشان نمی‌دهند. برای بررسی‌های جاری، [اعتبارسنجی](../validation.fa.md) را ببینید.

این ممیزی قابلیت‌های API، مالک پیاده‌سازی، بررسی اجراشده و کار وابسته به بهره‌بردار
یا provider را تفکیک می‌کند. [گزارش اجرای محلی](independent-api-verification.fa.md)
شاهد تاریخ‌دار است و اجرای سرویس میزبانی‌شده را ادعا نمی‌کند.

مسیرها نسبت به ریشهٔ مخزن یا، در حالت کوتاه‌شده، نسبت به `src/` هستند. رفتار عمومی HTTP را مجموعهٔ
Bruno، DTO انتقال و آزمون ارائه‌دهنده/HTTP مستند می‌کنند. SEO/CSP سایت، عملکرد و
دسترس‌پذیری/تصویر UI و رفتار درخواست پنل متعلق به مخزن فرانت مربوط هستند و نباید
به Hono منتقل شوند.

بازخوانی بعدی کد، پس از snapshot ورودی ارزیابی مستقل فهم کد، یک ایراد فرادادهٔ
پاسخ را آشکار کرد: کد زبان ذخیره‌شدهٔ پشتیبانی‌نشده از قبل پیام انگلیسی داشت،
اما `Content-Language` همان مقدار نامعتبر را اعلام می‌کرد. مرز HTTP/بومی‌سازی
اکنون هر دو را انگلیسی تعیین می‌کند. تنظیمات عمومی همچنان مقدار نامعتبر را رد
می‌کند و به‌روزرسانی مجاز بدون ترمیم خودکار DB ممکن است. رگرسیون مستقل از محیط
در `auth-invariants.test.ts` عدم تطابق قبلی را بازتولید و header انگلیسی پاسخ
خطا/اصلاح و پاسخ فارسی درخواست بعدی را بررسی می‌کند. زبان جایگزین اضطراری عمدی
بک‌اند و سیاست خطای صریح جداگانهٔ وب‌سایت حفظ شده‌اند؛
[بومی‌سازی API](../localization.fa.md) را ببینید.

پیشنهادهای قابل‌استفادهٔ دوبارهٔ F038/F081/F082/F085 نیز با
[تحویل نیازمندی و برنامهٔ پیاده‌سازی](../change-workflow.fa.md) و
[سیاست پایداری تست و مالک خطای ناپایدار](../test-reliability.fa.md) محلی پوشش
دارند. این‌ها قالب و قاعدهٔ مشخص هستند، نه سرویس میزبانی وظیفه یا شاهد رعایت آن
در تغییرهای آینده.

## اجرا در این ممیزی

- مجموعهٔ موجود API پیش از تمرین جدید هر ۱۰۹ سناریو را موفق گذراند؛ چهار سناریوی
  معماری و نه سناریوی یکپارچگی کاتالوگ نیز جداگانه موفق بودند.
- `npm run validate -- full` پس از افزوده‌ها و اصلاح فرادادهٔ زبان، هر ۱۵ بررسی
  الزامی را موفق گذراند: ۱۱۳ سناریوی API، ۱۶ قرارداد منتخب، ۳۹ استقرار، ۱۸ ابزار، ۱۴ راهنما، شش رگرسیون
  مرز و نه کاتالوگ؛ دروازهٔ مرز چهار سناریوی معماری را هم اجرا کرد. بعضی دستورها
  هم‌پوشانی دارند؛ شمارش برای هر دستور است، نه جمع آزمون یکتا. typecheck، lint،
  قالب‌بندی، Knip و دروازهٔ ساخت TypeScript بومی موفق بودند.
- `npm run test:recovery` هر سه سناریوی جدید بازیابی/رخداد را موفق گذراند. هر
  سناریو فرایند فرزند محدودشده دارد و درخت TEMP بررسی‌شده پس از خروج حذف می‌شود؛
  typecheck، Knip و راهنما نیز پس از افزوده‌ها موفق بودند.
- audit آنلاین تازه از دستور اصلی کامل شد: صفر high/critical و چهار moderate
  در زنجیرهٔ MinIO شامل `minio`، `query-string`، `decode-uri-component` و
  `stream-json`. دروازهٔ الزامی `--audit-level=high` است؛ خروج موفق معادل صفر
  آسیب‌پذیری نیست.

## تصمیم‌ها و پیشنهادهای باقی‌مانده

1. پیش از فعال‌سازی ثبت‌نام عمومی، بازیابی رمز یا تأیید ایمیل، ارائه‌دهندهٔ واقعی
   ارسال OTP را انتخاب و پیاده کنید. production فعلی کد ثابت توسعه را رد می‌کند
   و بدون ارسال، صریح شکست می‌خورد. adapter دارای موفقیت صوری ارسال اضافه نکنید.
2. برای چهار moderate، رفع upstream یا مهاجرت SDK MinIO را با بررسی مستقل برنامه‌ریزی
   کنید. downgrade پیشنهادی audit لزوماً patch سازگار نیست؛ اینجا override یا
   پنهان‌سازی یافته انجام نشد.
3. storage واقعی منتخب، بازیابی محافظت‌شدهٔ secret و نگهداری/RPO/RTO استقرار را
   تمرین کنید. تمرین محلی مصنوعی جدید، زمان‌بندی پشتیبان production، بازیابی سیاست
   MinIO یا میزبان لینوکس را ثابت نمی‌کند.
4. هنگام نیاز، collector/هشدار استقرار را تنظیم و شاهد خطای فرانت را با شناسهٔ API
   وصل کنید. رخداد ممیزی تغییرناپذیر را فقط برای نیاز مشخص محصول/مقررات اضافه کنید.
5. ابزار اختیاری فهم سورس و مقایسهٔ مدل را از runtime جدا نگه دارید. ارزیابی تازه
   باید طبق [روش ارزیابی](../comprehension-evaluation.fa.md) با شاهد واقعی ثبت شود.
