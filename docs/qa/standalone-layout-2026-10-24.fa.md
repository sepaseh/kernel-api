# گزارش اجرای API — ۲۰۲۶-۱۰-۲۴

[English](standalone-layout-2026-10-24.md) · [فارسی](standalone-layout-2026-10-24.fa.md)

این پرونده گزارشی تاریخی دربارهٔ ۲۴ اکتبر ۲۰۲۶ است؛ ادعاهای اجرای آن مستقلاً تأیید نشده‌اند و وضعیت کنونی پروژه را نشان نمی‌دهند. برای بررسی‌های جاری، [اعتبارسنجی](../validation.fa.md) را ببینید.

این گزارش نتیجهٔ اجرای محلی در تاریخ بالا است؛ شمارها متعلق به همان اجرا هستند و
برای سورس جدیدتر نتیجهٔ تازه محسوب نمی‌شوند.

## بررسی اجراشده

هر ۱۵ دروازهٔ الزامی پس از `npm ci` تمیز در ریشه گذشت: ۱۱۸ تست API شامل پنج تست کاتالوگ محلی، ۱۶ تست قرارداد HTTP، ۳۶ تست استقرار، شش تست مرز سورس، چهار تست معماری و ۱۵ تست راهنما. typecheck، lint، قالب‌بندی، Knip و build گذشتند. هر ۱۴ تست متمرکز tooling مربوط به API نیز گذشت. ممیزی وابستگی همان چهار یافتهٔ متوسط قبلی را دارد و یافتهٔ high/critical ندارد.

بستهٔ تولید native در محیط موقت واقعی، نصب ۱۵۳ وابستگی تولید، preflight، migration، ساخت مدیر، سلامت و ورود را گذرانده است. پوشهٔ انتشار و fixture موقت آن پاک شدند.

smoke واقعی داکر با ساختار ریشه گذشت: HTTPS، شناسهٔ انتشار ثابت، ساخت مدیر اول و رد ساخت تکراری، نشست، بررسی origin، اعلام صریح در دسترس نبودن ارسال OTP، ذخیره‌سازی عمومی/خصوصی و حفظ داده پس از تعویض کانتینر. lockfile تولید، سورس و migration ریشه واقعاً داخل image لینوکسی ساخته شدند. directive اختیاری frontend خارجی Dockerfile حذف شد و دستورهای استاندارد از frontend همراه BuildKit استفاده می‌کنند. پس از این تغییر هر ۳۶ تست استقرار دوباره گذشت.

نبود هر پنج builder موقت این تلاش‌ها تأیید شد. کانتینر، شبکهٔ اختصاصی، volume، image برنامه، کش builder و fixture داکر تست‌ها حذف شدند؛ image تازه‌دریافت‌شدهٔ ابزار مشترک BuildKit نیز پس از مجموعهٔ تست حذف شد. موجودی نهایی داکر صفر image، کانتینر، volume و بایت کش ساخت بود. global prune به کار نرفت.

## حدود بررسی

این نتایج اجرای CI میزبانی‌شده، انتشار تولید، فعال‌سازی systemd در Linux، تأیید دستی
screen reader یا تکمیل یکپارچه‌سازی وابسته به provider را ثابت نمی‌کنند. پاک‌سازی
Docker فقط منابع همان تست را پس از موفقیت و شکست حذف می‌کند؛ global prune مجاز نیست.
