# اعتبارسنجی ورودی

[English](input-validation.md) · [فارسی](input-validation.fa.md)

حد مشترک نام پروفایل در `src/contracts/profile.ts` است؛ DTOهای HTTP در فایل قرارداد
مالک خود یعنی `account.ts`، `auth.ts` و `settings.ts` قرار دارند. اعتبارسنجی برنامه
رشته را پیش از بررسی طول trim می‌کند و نبودن/خالی‌بودن patch اختیاری را از نوع
نامعتبر یا طول خارج از محدوده جدا می‌کند؛ اولی مقدار فعلی را نگه می‌دارد و دومی
پیش از هر نوشتن جزئی رد می‌شود. ثبت‌نام نام و رمز را پیش از مصرف OTP یا فراخوانی
provider بررسی می‌کند. حساب شخصی و کاربر مدیریت‌شده همین حدود را دارند. قید DB
و تراکنش حفاظت جداگانه هستند.

JSON باید application/json باشد و اندازهٔ واقعی آن حتی بدون Content-Length به
۶۴ کیلوبایت محدود است. مسیر آپلود ابتدا احراز هویت می‌کند و پیش از parse، بایت
واقعی multipart را به سقف پیکربندی‌شدهٔ فایل به‌علاوهٔ ۶۴ کیلوبایت برای قاب و
فیلدها محدود می‌کند. برنامه اندازهٔ فایل را جداگانه پیش و پس از خواندن بررسی
می‌کند. سقف پیش‌فرض Nginx برابر ۶ مگابایت و سقف پیش‌فرض فایل ۵ مگابایت است؛
آن‌ها را آگاهانه هماهنگ کنید. آزمون‌های مرتبط اعتبارسنجی و HTTP و پیش از commit
یا تحویل PR مجاز، `npm run validate -- full` را اجرا کنید. سازگاری HTTP را برای
مصرف‌کننده‌های مرتبط بررسی کنید.

## رفتار نام پروفایل

حد نام پس از trim برابر ۱۰۰۰ واحد UTF-16 جاوااسکریپت است؛ شمار بایت یا نویسهٔ دیداری
نیست. ثبت‌نام، ایجاد کاربر، ویرایش کاربر مدیریت‌شده و حساب همین ثابت را مصرف می‌کنند.

| ورودی                               | ایجاد/ثبت‌نام | patch پروفایل/کاربر  |
| ----------------------------------- | ------------- | -------------------- |
| رشتهٔ غیرخالی trimشده تا ۱۰۰۰ واحد  | پذیرش         | تغییر فیلد           |
| بیش از ۱۰۰۰ واحد                    | 400           | 400؛ بدون نوشتن جزئی |
| نبودن، خالی یا فقط فاصله            | 400؛ الزامی   | حفظ مقدار موجود      |
| عدد، boolean، آرایه، object یا null | 400           | 400؛ بدون نوشتن جزئی |

patch تک‌نامی به نام دوم نیاز ندارد. نام خالی در کنار تغییر پشتیبانی‌شدهٔ دیگر
مقدار موجود را حفظ می‌کند؛ درخواست بدون فیلد مؤثر پشتیبانی‌شده با 400 رد می‌شود.
تغییر موبایل نیز طبق [انتقال HTTP](http-transport.fa.md) به تأیید شمارهٔ جدید نیاز دارد. فیلد ناشناخته ذخیره نمی‌شود؛ این به معنی رد کلید ناشناخته در همهٔ endpointها
نیست. دادهٔ ذخیره‌شده بازنویسی نمی‌شود. پوشش message، شناسهٔ درخواست، status و زبان
تنظیم‌شدهٔ خطا حفظ می‌شوند.

ریشهٔ JSON باید object غیر null باشد. JSON خراب، آرایه و مقدار primitive با 400،
نوع رسانهٔ نامناسب با 415 و بدنهٔ بزرگ با 413 رد می‌شوند. سقف ۶۴ کیلوبایت روی بایت
واقعی stream حتی بدون Content-Length یا با اعلام کوچک‌تر اعمال می‌شود.
