# Branch protection policy

[English](branch-protection.md) · [فارسی](branch-protection.fa.md)

ادغام به موفقیت CI، تأیید CodeRabbit برای سر فعلی PR، قبولی دروازهٔ کیفیت
SonarQube Cloud برای همان کامیت و حل گفتگوهای بازبینی نیاز دارد. شاهد مفقود، در
انتظار، ناموفق، انجام‌نشده یا محدود به سهمیه، ادغام را بسته نگه می‌دارد. این قانون
برای مدیران هم اعمال می‌شود؛ تأیید قدیمی بی‌اعتبار، شاخهٔ به‌روز و تاریخچهٔ خطی
الزامی و force push و حذف شاخه ممنوع است.

در مرحلهٔ قواعد کار، بررسی‌های **Bootstrap governance (API not published)** و
**SonarQube Cloud analysis** از GitHub Actions و **SonarCloud Code Analysis** از
برنامهٔ SonarQube Cloud الزامی‌اند. بررسی **Review approval gate** باید از ناشر
مستقل مورد اعتماد در [راهنمای قفل ادغام](review-gate.fa.md) برسد. شرایط CI هر مرحله
تنها پس از تأیید اجرای واقعی بررسی‌های جانشین عوض شوند؛ برای ادغام کار ناقص، یک
شرط الزامی را حذف نکنید.

تعداد عمومی تأییدها، تأیید یک ربات مشخص را اجباری نمی‌کند؛ وضعیت پیشرفت موفق
CodeRabbit هم ممکن است به بازبینی انجام‌نشده مربوط باشد. ناشر مورد اعتماد، هویت
ربات، بازبینی واقعی `APPROVED` روی همان سر، نتیجهٔ فعلی CI و Sonar، صفحه‌بندی کامل
گفتگوها و ثابت‌بودن سر و مبنا را بررسی می‌کند. کد، سیاست و کلید امضای ناشر نباید
تحت کنترل PR باشند.

شاخهٔ `main` خالی اولیه هنوز کد گردش کار مورد اعتماد ندارد. تا نصب و اتصال ناشر
مستقل، شرط قفل ادغام تأمین نمی‌شود و PRها مسدود می‌مانند. گردش کار سر PR نباید
مجوز ادغام خودش را صادر کند و این مانع برای راه‌اندازی حذف نشود. CODEOWNERS همچنان
پیشنهاد بازبین است و جای این شروط اجباری را نمی‌گیرد.
