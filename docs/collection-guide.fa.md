# Bruno و قرارداد HTTP

[English](collection-guide.md) · [فارسی](collection-guide.fa.md)

پوشهٔ collection/ را در Bruno باز و طبق [راهنمای مجموعه](../collection/README.fa.md)
یک محیط محلی با مقادیر مصنوعی بسازید. هر عملیات
index.bru برای روش، مسیر، احراز هویت، ورودی و یادداشت قرارداد دارد و در موارد
لازم نمونهٔ JSON با نام status هم ارائه می‌شود. پاسخ موفق بدون بدنه می‌تواند
نمونهٔ JSON نداشته باشد. نمونه، قرارداد HTTP را توضیح می‌دهد؛ مسیر Hono و سرویس برنامه آن را
پیاده می‌کنند. رمز یا token واقعی را در collection ذخیره نکنید.

برای تغییر رفتار قابل مشاهده، درخواست/یادداشت/نمونه، نوع مالک قابلیت در src/contracts
و رفتار مسیر/برنامه را با هم اصلاح کنید. آزمون متمرکز HTTP و persistence/مجوز، سند
جاری و هماهنگی مصرف‌کنندهٔ مرتبط را انجام دهید. فیلد snake_case، status و زبان پاسخ
انتخاب‌شده از تنظیمات را حفظ کنید؛ محتوای واردشده توسط کاربر ترجمه نمی‌شود.

آزمون برای خطا، وضعیت واقعی fixture یا ورودی نامعتبر ایجاد می‌کند. query/header
انتخاب status ساختگی یا endpoint بازرسی پاسخ وجود ندارد. شمای DB، چیدمان ذخیره‌سازی
و استقرار قرارداد پیاده‌سازی/عملیات هستند؛ [معماری](architecture.fa.md)،
[پایگاه داده](database-schema.fa.md) و [استقرار](deployment.fa.md) مرجع آن‌ها هستند.
آزمون‌های مرتبط HTTP و collection و `npm run check:boundaries` را اجرا کنید؛
پیش از commit یا تحویل PR مجاز، `npm run validate -- full` را اجرا کنید.

## تحویل قرارداد صفحهٔ کلاینت

هنگام برنامه‌ریزی صفحهٔ مصرف‌کنندهٔ API، کار `http-contract` در
[.agents/navigation.json](../.agents/navigation.json) را دنبال کنید. پیش از پیشنهاد
درخواست یا حالت رابط، عملیات Bruno، DTO، مسیر، سرویس و آزمون مالک را باز کنید.
رفتار موجود را از تغییر درخواستی قرارداد جدا ثبت کنید؛ برای کامل نشان‌دادن طرح،
endpoint، مجوز، فیلد یا خطا اختراع نکنید.

- روش/مسیر، نیاز احراز، فیلد ورودی/خروجی، رفتار optional/null/default و status موفق
  هر عملیات را مشخص کنید. snake_case انتقال را حفظ و عملیات و سورس مالک را شاهد کنید؛
  تنها شکل TypeScript کافی نیست.
- حد فیلد، قالب و status شکست را از اعتبارسنجی برنامه و رفتار HTTP استخراج کنید؛
  [اعتبارسنجی ورودی](input-validation.fa.md) و
  [قاعدهٔ collection](../.agents/rules/api-collection.md) مرجع‌اند. حالت انتظار، موفقیت
  و شکست ذخیره را مشخص کنید؛ کنترل کلاینت اجرای سیاست سرور را ثابت نمی‌کند.
- خواندن عمومی، خواندن احرازشده و مجوز نوشتن را جدا مشخص کنید. برای صفحهٔ فهرست،
  فیلتر، مرتب‌سازی، پیش‌فرض/سقف صفحه‌بندی و تعداد پاسخ واقعی همان عملیات را دنبال کنید؛
  اگر فهرستی نیست، نامرتبط بودن این موارد را ثبت کنید.
- رفتار نشست/کوکی و پاسخ بدون احراز/غیرمجاز را با کار `auth-session` و
  [توالی نشست](sequences.fa.md) دنبال کنید. guard انتقال/نشست فرانت‌اند مصرف‌کننده
  حفظ شود؛ این API مؤلفهٔ آن را انتخاب نمی‌کند.
- برای رسانه، URL عمومی را از metadata خصوصی، visibility مجاز آپلود، فیلد multipart
  و خطای اندازه/نوع از طریق `deployment` جدا کنید. لوگوی تنظیمات از فایل عمومی
  `POST /files` می‌آید؛ object key شاهد خواندن عمومی نیست.
  [سرویس فایل](../src/application/files.ts) مرجع است.
- شیء زبان ذخیره‌شدهٔ پاسخ API، شامل جهت، تقویم و نام عمومی را مصرف کنید؛ آن را از کد
  زبان یا ترجیح بازدیدکننده حدس نزنید. کار `active-language` و
  [ترجمه](localization.fa.md) را دنبال کنید. کتابخانهٔ مؤلفه، چیدمان، دسترس‌پذیری
  و بررسی ظاهر متعلق به راهنمای خود فرانت‌اند است.

برای صفحهٔ ظاهر/لوگو/زبان، [مسیر تنظیمات](../src/presentation/http/routes/settings.ts)
شامل `GET /settings` عمومی با `Cache-Control: no-store`، `GET /languages` احرازشده
و `PUT /settings` محافظت‌شده است.
[سرویس تنظیمات](../src/application/settings.ts)،
[DTO پاسخ](../src/contracts/settings.ts) و
[عملیات ویرایش](../collection/settings/update/index.bru) را بخوانید: هر دو palette
کامل الزامی‌اند؛ شناسهٔ لوگو اختیاری و متعلق به فایل عمومی است. این PUT هر دو palette
و انتخاب لوگو را جایگزین می‌کند: در ذخیرهٔ نامرتبط، `dark_logo.id`/`light_logo.id`
موجود را به صورت `dark_logo_id`/`light_logo_id` نگه دارید، چون حذف شناسه از درخواست
انتخاب همان لوگو را پاک می‌کند.
[آداپتور ذخیره‌سازی](../src/infrastructure/persistence/settings.ts) مرجع است.
ویرایشگر عادی دارای
`settings.update` مجوز ظاهر را حفظ و `language_code` را حذف می‌کند؛ فقط مدیر کل
می‌تواند آن را تغییر دهد. ورودی سازگارِ صریحاً بدون تغییر ویرایشگر عادی نیز نوشته
نمی‌شود تا تغییر هم‌زمان مدیر بازنویسی نشود. پس از موفقیت، تنظیمات پاسخ را اعمال و
پاسخ مستند ورودی نامعتبر، بدون احراز، غیرمجاز و زبان/لوگوی ناموجود را در نظر بگیرید.
این صفحه قرارداد فهرست/صفحه‌بندی نیاز ندارد.
