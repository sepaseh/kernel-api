# مرزهای اجرای API

[English](api-runtime.md) · [فارسی](api-runtime.fa.md)

این API مستقل، مسیرهای HTTP، سرویس‌های مستقل از چارچوب و آداپتورهای زیرساخت
را در یک checkout ترکیب می‌کند. پایگاه داده، احراز هویت و ذخیره‌سازی متعلق به
API هستند و کلاینت‌ها از HTTP استفاده می‌کنند. [معماری](architecture.fa.md)،
[انتقال HTTP](http-transport.fa.md) و [محدودیت‌های پایگاه داده](database-schema.fa.md)
را ببینید.

تا تکمیل مقداردهی، listener پاسخ 503 می‌دهد. آزمون‌های اجرای محلی از دادهٔ
مصنوعی استفاده می‌کنند و اثبات آمادگی تولید یا ارسال واقعی OTP نیستند. استقرار
و بازیابی اپراتور فرایندهای جداگانه‌اند؛ [استقرار](deployment.fa.md) و
[پشتیبان و بازیابی](backup-restore.fa.md) را ببینید.

## حذف کاربر و نقش

DELETE /users/{user_id} احراز هویت، مجوز users.delete و محافظ حذف خود و آخرین مدیر
فعال سیستم را حفظ می‌کند. عضویت نقش و ارجاع metadata فایل آپلودشده در تراکنش حذف
بررسی می‌شود. کاربر دارای مصرف با HTTP 409 و همان شکل پاسخ {message} در زبان
ذخیره‌شدهٔ سیستم رد می‌شود و پیام از فراخواننده می‌خواهد پیش از تلاش دوباره مصرف را
رفع کند. در خطا، کاربر، انتساب، metadata/شیء فایل و رکورد هویت دست‌نخورده می‌مانند؛
علامت حذف نرم یا قطع خاموش رابطه وجود ندارد.

کاربر مجاز و بدون مصرف برای همیشه حذف و 200 OK بدون بدنه دریافت می‌کند؛ فقط پس از
این حذف مجاز، session و account احراز هویت متعلق به او cascade می‌شوند.
DELETE /roles/{role_id} هم نقش تخصیص‌یافته را با ۴۰۹ راهنما رد و انتساب را حفظ
می‌کند؛ حذف مجاز نقش مجوزهای متعلق به آن را پاک می‌کند. این رکورد فنی متعلق به
موجودیت با مصرف ورودی کسب‌وکار تفاوت دارد.

عضویت کاربر را با عملیات جایگزینی نقش موجود و مجاز رفع کنید. اکنون endpoint حذف
فایل یا تغییر سازندهٔ آن پیاده نشده و این ارجاع مانع واقعی حذف می‌ماند. برای موفق‌کردن
درخواست حذف کاربر، endpoint ساختگی اضافه، شناسهٔ سازنده پاک یا شیء فایل حذف نکنید.
