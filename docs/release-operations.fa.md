# Immutable releases, upgrades and rollback

[English](release-operations.md) · [فارسی](release-operations.fa.md)

مالک انتشار artifact تغییرناپذیر را با شواهد تأیید و source، lock، پلتفرم، checksum،
مبدأ عمومی، مرجع تنظیمات و سطح مهاجرت را ثبت می‌کند. اپراتور مجاز همان artifact
را فعال می‌کند. گردش‌کار دستی metadata انتشار به تنظیم و تأیید جداگانه در
راه دور نیاز دارد و نباید زیرساخت را deploy کند. [انتشار دستی](releasing.fa.md)
را ببینید.
پنل و وب‌سایت مستقل باید با قرارداد HTTP API سازگار بمانند. ترجمه و قرارداد محلی
عمداً مستقل‌اند و registry یا هماهنگی اجباری ترجمه میان مخزن‌ها فرض نشده است.

در Linux بومی، با deploy:package از source مورد اعتماد بسته بسازید، وابستگی را
روی OS/CPU هدف نصب، مالکیت و مجوز را بررسی و release قبلی را حفظ کنید. پیش از
تعویض /srv/kernel-api/current، مهاجرت را روی restore جدا تمرین، نوشتن و API را
متوقف و از شروع دوباره توسط supervisor جلوگیری کنید. پس از تأیید توقف کامل،
backup هماهنگ DB/فایل را طبق روال بازیابی، شامل فایل‌های journal یا WAL مربوط
به SQLite، بگیرید. symlink جاری را اتمیک به انتشار کامل تأییدشده تغییر و محیط
محافظت‌شده را اعتبارسنجی کنید و سپس شروع کنید. پیش
از بازگشایی، health، release marker، ورود/مجوز و فایل عمومی/خصوصی را بسنجید و
log را با SERVER_RELEASE_ID مطلوب بررسی کنید.

Docker از tag تغییرناپذیر و نام پروژه و volume ثابت استفاده می‌کند. RELEASE_ID
نسخهٔ تازه را انتخاب می‌کند؛ tag منتشرشده را بازنویسی و volume واقعی را حذف نکنید.
تنظیمات و مسیر گواهی را پیش از up -d --wait بررسی کنید.

خطای health، نشست، مجوز یا یکپارچگی، نبود فایل، marker غلط یا تماس خارجی غیرمنتظره
باید rollout را متوقف کند. artifact قبلی، تنظیمات سازگار محافظت‌شده و نقطهٔ بازیابی
متناظر را با هم نگه دارید. اگر کد قدیمی schema فعلی را می‌فهمد، artifact قبلی را
فعال و بررسی کنید؛ وگرنه اول SQLite و فایل هماهنگ را restore کنید. image یا symlink
به‌تنهایی مهاجرت را برنمی‌گرداند. اپراتور، رخداد و release، شواهد، بازهٔ ازدست‌رفتن
داده و مدت بازیابی را ثبت و log و کار اصلاحی را حفظ کنید؛ وسط rollback تغییر
نامرتبط و عجولانه ندهید.

[روش‌های استقرار](deployment.fa.md)، [بازیابی](backup-restore.fa.md) و
[staging و smoke دستی](staging.fa.md) را ببینید. موارد امنیتی را به‌صورت خصوصی با
نگهدارندگان هماهنگ کنید.
