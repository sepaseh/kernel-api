# مرحلهٔ پایه و اعتبارسنجی

[English](bootstrap.md) · [فارسی](bootstrap.fa.md)

این مجموعه در مرحلهٔ **زیرساخت پایه** است. فهرست اعلام‌شدهٔ آن در
[bootstrap-policy.json](../.github/bootstrap-policy.json) قرار دارد و مقدار
`applicationReady` همچنان **false** است. پروژه شامل ماژول‌های خالص قرارداد،
اجزای پایهٔ لایهٔ کاربرد مستقل از فریم‌ورک و رابط‌های آداپتر است. سرویس‌های
قابلیت، مسیرهای HTTP، پایگاه داده و migration، آداپترهای واقعی احراز هویت و
ذخیره‌سازی و استقرار در این مرحله وجود ندارند.

برای نقشهٔ سورس فعلی [README](../README.fa.md) و برای روش تغییرات
[راهنمای مشارکت](../CONTRIBUTING.fa.md) را بخوانید. این مرحله ابزار توسعهٔ
محلی دارد و وابستگی زمان اجرا ندارد؛ API راه‌اندازی نمی‌کند.

## مجموعهٔ دقیق فایل‌ها و بررسی کامل مرحله

از Node.js در [`.nvmrc`](../.nvmrc)، محدودهٔ پشتیبانی‌شده در
[`package.json`](../package.json) و npm 12 استفاده کنید:

```sh
npm ci
npm run validate -- full
```

[فهرست مرجع اعتبارسنجی](../.agents/validation.json) تمام بررسی‌های الزامی
این مرحله را مشخص می‌کند: یکپارچگی مجموعهٔ فایل‌ها، audit وابستگی‌ها، مرزهای
سورس، نوع‌ها، lint، قالب‌بندی، تست همراه با پوشش و تست ابزار audit.
پیش از commit یا تحویل PR که صریحاً مجاز شده است، تمام پروفایل `full` را
اجرا کنید. تست محدود حین توسعه جای آن را نمی‌گیرد.

checkout یا خروجی جداگانهٔ محتوای دقیق پیشنهادی را بررسی کنید. محافظ فهرست،
فایل نگهداری‌شدهٔ مفقود یا اضافی، لینک نمادین و مسیر خصوصی را رد می‌کند؛
سورس کامیت‌نشدهٔ اضافه نباید PR ناقص را کامل نشان دهد. فهرست مجاز، محتوای مخزن
را تعریف می‌کند. **سقف ۱۰۰ فایل برای فهرست فایل‌های تغییرکردهٔ هر PR در GitHub
است** و اندازهٔ آن فهرست مجاز را محدود نمی‌کند.

تست‌های پایه به محیط واقعی، پایگاه داده، bucket یا API در حال اجرا نیاز
ندارند. اسرار و دادهٔ زمان اجرا را وارد سورس یا fixtureهای تست نکنید.

## محدودهٔ شواهد

مجموعهٔ تست، بررسی اندازهٔ PR و فهرست فایل‌ها را حفظ می‌کند و تست‌های خالص
پایه، اعتبارسنجی، مرزهای سورس، اجراکنندهٔ اعتبارسنجی و ابزار audit را اضافه
می‌کند. محدودهٔ فعلی شامل کنترل مجوز، خطاهای معنایی، دسترسی‌های مرجع،
هویت احراز هویت و فرادادهٔ زبان است.

دستور `npm run test:coverage` از کد پایه و اسکریپت‌های مخزن که در همین
checkout تست شده‌اند فایل واقعی `coverage/lcov.info` تولید می‌کند. تست
جداگانهٔ ابزار audit نیز در پروفایل کامل الزامی است. گزارش تولیدشده commit
نمی‌شود. پوشش پایه و ابزارها، پوشش HTTP، پایگاه داده، سرویس احراز هویت یا
ذخیره‌سازی نیست و آمادگی API قابل اجرا را ثابت نمی‌کند.

از [CI موجود](../.github/workflows/ci.yml) و
[گردش‌کار Sonar](../.github/workflows/sonar.yml) استفاده کنید؛ گردش‌کار
scanner تکراری نسازید. پیش از گزارش موفقیت، اجرای واقعی میزبانی‌شده،
revision تحلیل‌شده و دروازهٔ کیفیت ارائه‌دهنده را بررسی کنید.
[تنظیم Sonar](sonarqube.fa.md) را ببینید.

## چرخهٔ Pull Request

1. روی شاخهٔ مشخص `codex/<purpose>` کار و کل تفاوت با مبنا را بررسی کنید.
2. هر PR حداکثر **۱۰۰ مورد فایل تغییرکرده در GitHub** داشته باشد. افزودن،
   حذف، تغییر نام و فایل باینری حساب می‌شوند؛ تغییر نام در GitHub یک مورد است.
3. تمام بررسی‌های مرحلهٔ فعلی را روی مجموعهٔ دقیق پیشنهادی اجرا و revision،
   مرحله، دستورها، نتیجه‌ها و محدودیت‌ها را ثبت کنید.
4. با اجازهٔ صریح، PR را با [قالب](../.github/PULL_REQUEST_TEMPLATE.md)
   منتشر کنید. کار ناقص در حالت Draft بماند.
5. یافته‌های CodeRabbit را بخوانید، عیب‌های عملی را اصلاح و بررسی‌های مرتبط
   را تکرار کنید. بازبینی اجرا‌نشده، بازبینی کامل نیست. در چرخهٔ مجاز در صورت
   نیاز یک بار درخواست بازبینی کنید؛ سهمیه را رعایت و انتظار بازبینی را اعلام
   کنید.
6. تحلیل واقعی Sonar و دروازهٔ کیفیت بومی آن را جداگانه تأیید کنید.
7. ادغام فقط پس از موفقیت CI الزامی، بررسی‌های بومی CodeRabbit و Sonar،
   بازبینی تأییدشده و حل گفتگوها انجام شود.
   [حفاظت شاخه](branch-protection.fa.md) را رعایت کنید؛ وجود تنظیمات یا وضعیت
   پیشرفتِ بازبینی اجرا‌نشده شاهد بازبینی واقعی نیست.

[سیاست PR](../.github/workflows/pr-policy.yml) کد شاخهٔ پیش‌فرض مورد اعتماد
را با دسترسی فقط‌خواندنی و روی کامیت ثابت `github.workflow_sha` اجرا می‌کند.
در این رویداد دارای دسترسی، کد head مربوط به PR یا checkout مقصد بررسی‌نشده
را اجرا نکنید. صفحه‌بندی کامل و ثابت بودن head و base مربوط به PR برای شاهد
تعداد فایل‌ها الزامی است.

## ورود به مرحلهٔ قابل اجرا

سرویس‌های قابلیت، انتقال HTTP و آداپترهای واقعی را با تغییرات منسجم و
بازبینی‌شده اضافه کنید. هنگام ورود این پیاده‌سازی‌ها تمام تست‌های HTTP،
پایگاه داده، احراز هویت و ذخیره‌سازی را فعال و پروفایل کامل مرجع را گسترش
دهید. فهرست فایل‌ها، گردش‌کارها، محدودهٔ تحلیل و نام بررسی‌های حفاظت شاخه را
هماهنگ به‌روز کنید؛ پیش از کنار گذاشتن بررسی قدیمی، اجرای بررسی جایگزین را
تأیید کنید.

موفقیت بررسی‌های پایه مجوز true کردن آمادگی برنامه نیست. گسترش بی‌ضابطهٔ
فهرست مجاز، رفتار نمایشی یا سورس کامیت‌نشدهٔ نامرتبط را شاهد کارکرد API قابل
اجرا ندانید. سقف ۱۰۰ فایل برای هر PR در مراحل بعد نیز حفظ شود.
