# بازبینی احراز هویت و نشست

[English](authentication-review.md) · [فارسی](authentication-review.fa.md)

هنگام تغییر احراز هویت، نشست یا عملیات مرتبط از این فهرست استفاده کنید. موارد
زیر پرسش‌های بازبینی و مرزهای موجود هستند و گواه ممیزی بیرونی یا آمادگی تولید
نیستند.

1. برای عملیات نیازمند احراز هویت، بررسی کنید اقدام‌کننده هنگام عملیات نشست
   فعال و هر مجوز جاریِ لازم را دارد. ورود و بازیابی رمز به نشست قبلی نیاز
   ندارند؛ در عوض بررسی اعتبارنامه یا OTP مربوط به آن‌ها را ارزیابی کنید. برای
   تغییر شمارهٔ حساب دیگر، شرط مدیر سیستم فعال و ریسک اعتبارسنجی صرفاً شمارهٔ
   جدید را در نظر بگیرید.

2. هدف، مقصد و انقضای OTP را بررسی کنید. در تغییر موبایل اتصال به اقدام‌کننده،
   نشست و حساب هدف را نیز بررسی کنید؛ شکست تأیید یا تغییر نباید کد را به‌صورت
   ناقص مصرف کند. آداپتور فعلی ارسال OTP در تولید را فراهم نمی‌کند.

3. در تغییر یا بازیابی رمز و بازنشانی مدیریتی، مالکیت اعتبارنامه، بازگشت
   تراکنش در خطا و ابطال نشست‌های قبلی را بررسی کنید. شکست refresh کلاینت را با
   ابطال نشست سمت سرور یکسان نگیرید.

4. Origin و CORS مرورگر، ویژگی‌های کوکی و حذف اطلاعات حساس از پاسخ و گزارش را
   بررسی کنید. محدودکنندهٔ تلاش احراز هویت محلیِ هر فرایند است و کنترل توزیع‌شده
   یا مشترک نیست.

5. بررسی کنید ساخت مدیر اولیه JSON محافظت‌شده را از ورودی استاندارد می‌گیرد،
   پایگاه دادهٔ دارای کاربر را رد می‌کند، هویت را اتمیک می‌سازد و نشست صادر نمی‌کند.
   آزمون‌ها باید از پایگاه دادهٔ مصنوعی و موقت استفاده کنند.

6. تغییر ناسازگار HTTP و برنامهٔ انتشار را با کلاینت‌های مستقل بررسی کنید.
   آزمون محلی تنظیم درست کلاینت مستقر، ارائه‌دهندهٔ OTP یا زیرساخت را اثبات نمی‌کند.

[آداپتورهای احراز هویت](../auth-adapters.fa.md)، [تغییر شماره](../http-transport.fa.md)،
[مدل تهدید](threat-model.fa.md) و آزمون‌های یکپارچه‌سازی
[`auth-bootstrap-integration.test.mjs`](../../scripts/auth-bootstrap-integration.test.mjs)
و [`auth-identity-integration.test.mjs`](../../scripts/auth-identity-integration.test.mjs)
را ببینید.

bootstrap آفلاین JSON محافظت‌شدهٔ STDIN می‌گیرد، ورودی نامعتبر را پیش از DB رد،
seed را غیرفعال و هر کاربر قبلی را رد می‌کند؛ نشست یا توکن نمی‌سازد. اعتبارسنجی
تولید مرحلهٔ جداگانهٔ ضروری اپراتور است.

آزمون‌های API هم‌زمانی، rollback تراکنش، خروج امن، Origin نامعتبر، حدود رمز،
شکست provider و پاک‌سازی log را پوشش می‌دهند. آزمون پراکسی و bearer در مخزن
مصرف‌کننده است و سازگاری HTTP در انتشار مستقل باید سنجیده شود. نمایش امنیت را
بدون مجوز روی دادهٔ واقعی یا تولید اجرا نکنید.
