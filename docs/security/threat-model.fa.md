# مرزهای اعتماد و تهدیدهای API

[English](threat-model.md) · [فارسی](threat-model.fa.md)

این مدل وضعیت منتشرشدهٔ اجرای محلی را توضیح می‌دهد و ارزیابی کامل امنیت محیط
تولید نیست. API مالک احراز هویت، مجوز، پایگاه داده و ذخیره‌سازی اشیاست؛
کلاینت‌های مستقل از قرارداد HTTP استفاده می‌کنند. میزبان، شبکه، اسرار، تنظیمات
ذخیره‌سازی و فرایند انتشار بر عهدهٔ اپراتور است.

## دارایی‌ها و مرزها

- رمز، OTP، نشست و اسرار باید از افشا یا استفادهٔ مجدد محافظت شوند؛ عملیات حساب
  و مدیریت باید کاربر احراز‌شدهٔ جاری را بررسی کنند.
- نقش‌ها، مجوزها و آخرین مدیر سیستم فعال از عملیات مدیریتی محافظت می‌کنند.
  تغییرات هم‌زمان نباید قواعد ثبت داده را دور بزنند.
- دادهٔ کسب‌وکار و فرادادهٔ فایل با محدودیت‌ها و تراکنش‌های پایگاه داده محافظت
  می‌شوند. محتوای فایل از مرز جداگانهٔ ذخیره‌سازی می‌گذرد و در صورت شکست ثبت
  فراداده ممکن است به عملیات جبرانی نیاز داشته باشد.
- مرز HTTP ورودی نامطمئن، Origin مرورگر و اندازهٔ بدنه را بررسی می‌کند. گزارش‌ها
  باید برای بررسی رخداد مفید باشند، بدون افشای اعتبارنامه، مسیر خام درخواست یا
  جزئیات خطای ارائه‌دهنده.
- ذخیره‌سازی محلی و MinIO به فایل‌سیستم یا شبکهٔ تحت کنترل اپراتور وابسته است.
  پوشهٔ محلی باید در اختیار فرایند API باشد؛ بررسی متنی مسیر جلوی درج symlink
  توسط کاربر میزبان را نمی‌گیرد. MinIO به bucket اختصاصی و، خارج از `localhost`
  یا آدرس loopback صریح، به TLS نیاز دارد.

## سناریوهای مهم

درخواست تغییر از مرورگر با Origin نامعتبر رد می‌شود. درخواست بدون Origin نیز
اگر کوکی یا فرادادهٔ fetch مرورگر داشته باشد رد می‌شود؛ نبود Origin به‌تنهایی
روش مجوزدهی عمومی نیست. بررسی مجوز و نشست فعال برای کلاینت مرورگری و غیرمرورگری
همچنان ضروری است. [انتقال HTTP](../http-transport.fa.md) را ببینید.

تغییر شمارهٔ موبایل فقط **شمارهٔ جدید** را اعتبارسنجی می‌کند. تغییر شمارهٔ حساب
دیگری به مجوز `users.update` و مدیر سیستم فعال نیاز دارد؛ مدیری که شمارهٔ جایگزین را کنترل
می‌کند می‌تواند بدون رضایت مالک حساب آن را تغییر دهد. اپراتور باید این ریسک
بازیابی را در نظر بگیرد. OTP به کاربر اقدام‌کننده، نشست، حساب هدف و شماره‌های قدیم
و جدید متصل است و مجوز و تغییر در تراکنش دوباره بررسی می‌شوند.

ارسال OTP در تولید پیاده‌سازی نشده است. محدودکنندهٔ تلاش احراز هویت فقط در یک
فرایند کار می‌کند و تغییر تنظیمات bucket با سطح دسترسی بالا می‌تواند با بررسی
ذخیره‌سازی هم‌زمان شود. آزمون دادهٔ مصنوعی محلی اثبات حفاظت در برابر سوءاستفادهٔ
توزیع‌شده، عملکرد MinIO مستقر یا پاسخ به رخداد واقعی نیست. [آداپتورهای احراز
هویت](../auth-adapters.fa.md)، [ذخیره‌سازی](../object-storage.fa.md) و
[فهرست بازبینی امنیت](reviews.fa.md) را ببینید.
