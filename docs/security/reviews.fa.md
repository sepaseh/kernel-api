# بازبینی و بررسی‌های امنیت

[English](reviews.md) · [فارسی](reviews.fa.md)

برای تغییر مرز اعتماد از [مدل تهدید](threat-model.fa.md) و برای تغییر احراز
هویت از [فهرست نشست](authentication-review.fa.md) استفاده کنید. یافته‌ها را
با توجه به امکان سوءاستفاده، میزان مواجهه و اثر بر انتشار بررسی کنید و مسئول
و راه‌حل را ثبت کنید. وجود فایل workflow اثبات ارزیابی سامانهٔ مستقر نیست.

پروفایل کامل مخزن بررسی‌های [فهرست اعتبارسنجی](../../.agents/validation.json)،
از جمله audit وابستگی‌ها، را اجرا می‌کند. پیش از commit یا PR مجاز، روی نسخهٔ
پیشنهادی `npm run validate -- full` را اجرا کنید. پیش از درخواست CodeRabbit،
طبق [راهنمای Sonar](../sonarqube.fa.md) اجرای واقعی scanner، نتیجهٔ معیار کیفیت
و گزارش کامل موارد مرتبط را بررسی کنید؛ موفقیت scanner به‌تنهایی به‌معنای
موفقیت معیار کیفیت نیست. وضعیت CI و حفاظت شاخه را بررسی کنید و از روی فایل
workflow دربارهٔ وضعیت جاری نتیجه نگیرید.

[گردش‌کار DAST](../../.github/workflows/dast.yml) قالبی دستی و مخصوص staging
است که می‌تواند ترافیک تغییردهنده بفرستد. تنظیمات هدف از محیط staging خوانده
می‌شوند و میزبان تولید پیکربندی‌شده رد می‌شود؛ حفاظت محیط باید جداگانه تنظیم
و بررسی شود. بدون مجوز صریح هدف، آن را اجرا نکنید. پیش‌نیازها در
[staging](../staging.fa.md) آمده‌اند. برای آزمون محلی از اعتبارنامه و دادهٔ
مصنوعی استفاده کنید؛ اعتبارنامهٔ واقعی را نخوانید و از دادهٔ تولید استفاده
نکنید. آزمون مصنوعی محلی اثبات استقرار تولید یا بازبینی امنیتی شخص ثالث نیست.

این بند شیوهٔ پیشنهادی بازبینی است و سیاست تثبیت‌شدهٔ انتشار نیست: تغییر مرز اعتماد
را با threat model و auth را با checklist بسنجید و پیش از تولید
بازبینی انسانی متخصص داشته باشید. یافته را با قابلیت سوءاستفاده، افشا و اثر
انتشار اولویت، مالک و موعد بدهید. critical یا مورد فعال، استقرار را متوقف می‌کند؛
high نیازمند اصلاح یا استثنای صریح محدود با حفاظت جبرانی است. پذیرش این پیشنهاد
و اختیار صدور استثنا نیازمند تأیید مالک است.
