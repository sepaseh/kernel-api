# Create an issue

Read [issues](../../rules/issues.md), [Git workflow](../../rules/git.md) and
[safety](../../rules/safety.md). An issue is a durable handoff, not a transcript.

1. Confirm the repository and available host integration. Inspect relevant code,
   docs, tests and authorized open/closed issue metadata for duplicates; do not
   guess labels or template paths when access is unavailable.
2. State observed facts, expected outcome, impact, evidence and objective verification.
   Follow the issue rule's body shape and identify unknown facts with what was checked.
3. Keep one issue focused on one independently verifiable outcome. Exclude credentials,
   tokens, personal data, production payloads and sensitive security details. Use
   an available authorized private reporting channel for suspected vulnerabilities.
4. For draft-only work, return the proposed title and body locally. Create a GitHub
   issue only with explicit authorization, honoring authorization already provided.
5. Issue creation does not authorize implementation, comments on a duplicate,
   assignment, labels or project-status changes beyond the requested action.
   Report the URL when an issue is created.
