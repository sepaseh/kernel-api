# Create an issue

Follow the [issue rules](../../rules/issues.md) and
[remote action rules](../../rules/safety.md#external-systems).

1. Confirm the repository and available host integration. Inspect relevant
   source, documentation and tests. Check authorized open and closed issue
   metadata for duplicates and verify any applicable template.
2. Draft the title and body for one independently verifiable outcome. Include
   objective verification and identify unresolved facts. Follow the
   [security policy](../../../SECURITY.md) for suspected vulnerabilities.
3. Return the title and body for draft-only work. When publication is authorized,
   create the issue and report its URL. Verify authorization separately before
   changing issue metadata, commenting on a duplicate or starting implementation.
