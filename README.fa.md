# Kernel API

[English](README.md) · [فارسی](README.fa.md)

Kernel API یک پروژهٔ مستقل TypeScript است. مرحلهٔ فعلی
**داده‌های ترجمه (`localization-data`)** قراردادهای خالص HTTP، سرویس‌های
لایهٔ کاربرد، رابط‌های اختصاصی آداپتر هر قابلیت و ده کاتالوگ پیام API را ارائه می‌کند.
مقدار `applicationReady` همچنان **false** است؛ این مجموعه API مبتنی بر HTTP
را راه‌اندازی نمی‌کند.

## محدودهٔ فعلی

- [`src/contracts/`](src/contracts/) هفت ماژول خالص قرارداد برای حساب،
  احراز هویت، زبان‌ها، OTP، دسترسی‌ها، پروفایل و تنظیمات دارد.
- [`src/application/`](src/application/) شامل هفت ماژول پایهٔ کنترل مجوز،
  خطاها، هویت، واژگان ترجمه، مدل‌ها، دسترسی‌ها و اعتبارسنجی است؛ سرویس‌های حساب،
  احراز هویت، تقویم، فایل، نقش، تنظیمات و کاربر نیز در همین مسیر قرار دارند.
- [`src/application/ports/`](src/application/ports/) هشت رابط اختصاصی قابلیت
  برای ماندگاری داده، احراز هویت، OTP و ذخیره‌سازی شیء دارد. آداپتر واقعی در
  این مرحله ارائه نشده است.
- [`src/infrastructure/localization/catalogs/`](src/infrastructure/localization/catalogs/)
  کاتالوگ‌های کامل و تخت API برای عربی، آلمانی، انگلیسی، اسپانیایی، فارسی،
  فرانسوی، ایتالیایی، پرتغالی، روسی و ترکی دارد. فایل `index.ts` همان شیء اصلی
  هر کاتالوگ را ارائه می‌کند؛ موتور ترجمه در این مرحله وجود ندارد.
- تست‌های خالص با رابط‌های ساختگی و دادهٔ مصنوعی، سیاست‌های کاربرد و ترتیب
  عملیات و همچنین واژگان، جای‌گذاری متغیرها و مرز دادهٔ ثابت کاتالوگ‌ها را بررسی
  می‌کنند. تست‌های ابزارهای مخزن نیز مرزهای سورس، محدودهٔ دقیق
  انتشار، اندازهٔ PR، پردازش audit و اجرای اعتبارسنجی را پوشش می‌دهند.

[معماری](docs/architecture.fa.md) مالکیت کد، مرجع زبان، سیاست حذف قطعی و
محدودهٔ شواهد تست با رابط ساختگی را توضیح می‌دهد. مسیرهای HTTP، cookieها،
احراز هویت واقعی، پایگاه داده و migration، آداپتر ذخیره‌سازی و استقرار در این
مرحله منتشر یا اعتبارسنجی نشده‌اند. ابزارهای پروژه وابستگی توسعه‌ای دارند و
وابستگی زمان اجرا تعریف نشده است.

## نصب و اعتبارسنجی

از نسخهٔ Node.js در [`.nvmrc`](.nvmrc)، در محدودهٔ اعلام‌شده در
[`package.json`](package.json)، و npm همراه همان نسخهٔ Node استفاده کنید.
CI نیز همین نسخهٔ ثابت Node را بدون ارتقای جداگانهٔ npm به کار می‌برد.

```sh
npm ci
npm run validate -- full
```

[فهرست مرجع اعتبارسنجی](.agents/validation.json) هر نُه بررسی الزامی مرحلهٔ
فعلی را تعیین می‌کند: مجموعهٔ دقیق سورس، سیاست معنایی CI، audit وابستگی‌ها، مرزهای سورس، نوع‌ها،
lint، قالب‌بندی، پوشش واقعی تست و تست ابزار audit. این بررسی‌ها با دادهٔ مصنوعی
اجرا می‌شوند و به فایل محیط، پایگاه دادهٔ موجود یا API در حال اجرا نیاز ندارند.

تست‌ها فایل واقعی `coverage/lcov.info` را برای سورس کاربردی منتشرشده، دادهٔ کاتالوگ‌ها و ابزارهای
مخزن در همین checkout تولید می‌کنند. این گزارش پوشش پیاده‌سازی واقعی HTTP،
پایگاه داده، احراز هویت یا ذخیره‌سازی نیست و commit نمی‌شود.
[تنظیم Sonar](docs/sonarqube.fa.md) شواهد scanner و دروازهٔ ارائه‌دهنده را
توضیح می‌دهد.

## مشارکت

[راهنمای مشارکت](CONTRIBUTING.fa.md) و
[راهنمای مرحلهٔ انتشار](docs/bootstrap.fa.md) را بخوانید. هر PR حداکثر
**۱۰۰ مورد فایل تغییرکرده در GitHub** داشته باشد؛ این محدودیت برای تفاوت هر
PR است و تعداد کل فایل‌های مخزن را محدود نمی‌کند.

از CI، CodeRabbit و Sonar بومی و [حفاظت شاخه](docs/branch-protection.fa.md)
استفاده کنید. نتیجهٔ واقعی revision دقیق پیشنهادی را ثبت و پیش از commit یا
تحویل PR مجاز، بررسی کامل مرحله را اجرا کنید. پیش از درخواست CodeRabbit،
[پیش‌شرط head فعلی و صفر issue باز](docs/sonarqube.fa.md#پیش-از-درخواست-coderabbit)
را کامل کنید.
