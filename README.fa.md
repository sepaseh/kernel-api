# Kernel API

[English](README.md) · [فارسی](README.fa.md)

Kernel API یک پروژهٔ مستقل TypeScript است. مرحلهٔ فعلی **زیرساخت پایه**
تعریف‌های خالص قرارداد HTTP، اجزای پایهٔ لایهٔ کاربرد و رابط‌های آداپترهای
زیرساخت را فراهم می‌کند. مقدار `applicationReady` همچنان **false** است؛
این مجموعه هنوز API قابل اجرای HTTP ارائه نمی‌کند.

## محدودهٔ فعلی

- [`src/contracts/`](src/contracts/) هفت ماژول خالص قرارداد برای حساب،
  احراز هویت، زبان‌ها، OTP، دسترسی‌ها، پروفایل و تنظیمات دارد.
- [`src/application/`](src/application/) هفت ماژول پایهٔ مستقل از فریم‌ورک
  برای کنترل مجوز، خطاها، هویت، واژگان ترجمه، مدل‌ها، دسترسی‌ها و اعتبارسنجی دارد.
- [`src/application/ports/`](src/application/ports/) شامل هشت رابط آداپتر است.
  این رابط‌ها وابستگی‌ها را تعریف می‌کنند؛ پیاده‌سازی واقعی آن‌ها در این مرحله
  وجود ندارد.
- تست‌های پایه و اعتبارسنجی، رفتار خالص را بررسی می‌کنند. بررسی‌های مخزن نیز
  مرزهای سورس، یکپارچگی مجموعهٔ فایل‌ها، اندازهٔ PR، پردازش نتیجهٔ audit و
  اجراکنندهٔ اعتبارسنجی را پوشش می‌دهند.

سرویس‌های قابلیت‌ها، مسیرهای HTTP، اجرای احراز هویت، دسترسی پایگاه داده،
migrationها، آداپتر ذخیره‌سازی و استقرار در این مرحله وجود ندارند. ابزارهای
توسعه وابستگی‌های توسعه‌ای دارند و وابستگی زمان اجرا تعریف نشده است.
موفقیت بررسی‌های پایه، آمادگی یک API کامل را ثابت نمی‌کند.

## نصب و اعتبارسنجی

از نسخهٔ Node.js در [`.nvmrc`](.nvmrc)، در محدودهٔ اعلام‌شده در
[`package.json`](package.json)، و npm 12 استفاده کنید.

```sh
npm ci
npm run validate -- full
```

[فهرست مرجع اعتبارسنجی](.agents/validation.json) هر هشت بررسی الزامی مرحلهٔ
فعلی را تعیین می‌کند: مجموعهٔ دقیق سورس، audit وابستگی‌ها، مرزهای سورس،
نوع‌ها، lint، قالب‌بندی، پوشش واقعی تست و تست ابزار audit. این بررسی‌ها با
دادهٔ مصنوعی محلی اجرا می‌شوند و به فایل محیط، پایگاه دادهٔ موجود یا API
در حال اجرا نیاز ندارند.

تست‌ها فایل واقعی `coverage/lcov.info` را برای کد پایه و ابزارهای مخزن که در
همین checkout تست شده‌اند تولید می‌کنند. این گزارش پوشش پیاده‌سازی HTTP،
پایگاه داده، احراز هویت یا ذخیره‌سازی نیست. گزارش تولیدشده وارد commit نمی‌شود.
برای تفاوت اجرای scanner و قبولی دروازهٔ کیفیت ارائه‌دهنده،
[تنظیم Sonar](docs/sonarqube.fa.md) را ببینید.

## مشارکت

[راهنمای مشارکت](CONTRIBUTING.fa.md) و
[راهنمای مرحلهٔ پایه](docs/bootstrap.fa.md) را بخوانید. هر PR حداکثر
**۱۰۰ مورد فایل تغییرکرده در GitHub** داشته باشد؛ این سقف برای تفاوت همان PR
است و تعداد کل فایل‌های مجاز مخزن را محدود نمی‌کند.

از اتصال‌های بومی موجود CI، CodeRabbit و Sonar و
[حفاظت شاخه](docs/branch-protection.fa.md) استفاده کنید. وجود پیکربندی شاهد
اجرای بررسی میزبانی‌شده نیست. نتیجه‌ها را برای revision دقیق پیشنهادی ثبت کنید
و پیش از commit یا تحویل PR مجاز، تمام بررسی‌های مرحلهٔ فعلی را اجرا کنید.
